# Audited local evidence access

`integration::audit` adds a bounded process-local append-only record of authorized reads from immutable `StoredRun` values. It supplies no production identity provider or merge permission. `AuditExpectation` accepts only `Profile::Fixture` and is frozen from an independently prepared full work key, exact generation, producer identity and controller-selected producer principals. `freeze_git` uses the existing validated candidate preparation; this module does not authenticate Git by digest alone.

An opaque `specguard-evidence:v1:<run-id-sha256>:<artifact-kind>` identifies a contract, facts, report or domain artifact. It is never a filesystem path or a network URL. The resolver compares the exact generated reference and the independent work/generation expectation. A URI alone confers no access. File/HTTP URIs, unknown versions, query strings, encoding tricks and another artifact's authorization are rejected by exact comparison.

Each call requires two independent protected ports:

1. `EvidenceAccessPort` authenticates its external session and authorizes the exact URI, work digest, generation, envelope digest, artifact digest and fixed `read-evidence` purpose. It must not treat an echoed request as authorization. Test implementations explicitly simulate this port and are not production credentials.
2. GE `AuthorityProvider::verify_producer` freshly authenticates the actual envelope digest, exact expected producer and permitted principal. Recomputed SG/GE artifact verification supplies integrity only, never provenance or access permission. Technical BLOCK reports may be read by authorized auditors; this operation does not call them merge-eligible.

Time comes only from the protected `ConsumptionClock` port, never request/provider validity fields. The audit trail tracks a nondecreasing clock, including failed assessments, and samples again before releasing bytes. Access and producer validity must cover both observations. Exclusive mutable access serializes one trail's operations. The watermark and history are not durable or shared across processes; controllers must preserve their own protected clock and must not reset a trail to revive authority.

The record schema is fixed: sequence, trusted timestamp, predecessor digest, result enum, and hashes of work binding, envelope, selected artifact, authenticated actor/producer and contract/approval references. No URI text, source, artifact body, credentials, arbitrary causes or provider error strings are stored. Digests may correlate records; they are not encryption. Authentication failure does not store an unauthenticated actor. The previous record digest gives local causal ordering, not a signature or remotely authenticated audit log. A record digest is SHA-256 of its compact serde JSON with `record_digest` temporarily empty; recomputation alone never authenticates that chain. Historical records remain readable when specifically authorized; this API does not assert that a stored run is the current merge candidate.

Admission precedes owned clones and hashing: URI 128 bytes, individual controller/provider string 1 KiB, metadata encoding 64 KiB, at most 32 expected principals, and existing engine artifact byte limits. A provider can allocate internally before returning; this library bounds its own processing of that returned record and cannot sandbox provider code. At most 256 audit records are retained. If full, the resolver returns `Capacity` without releasing evidence and without claiming it recorded another attempt. All earlier records and stored evidence bytes remain unchanged.

`AuthorizedEvidence` is a private borrowed read receipt, not a serializable grant. Previously returned bytes cannot be recalled after revocation; a later access must perform fresh checks. This module does not import raw envelopes into history, persist secrets, resolve arbitrary remote URIs or choose a production authorization service. Broader controller integration and durable audit storage require separate contracts.
