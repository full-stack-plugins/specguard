# Fresh local evidence consumption

`RunHistory::consume_current` closes the gap between an immutable technical report and a current **fixture-profile** controller assessment. It is process-local and adds no production identity provider, durable store, signing, approval mutation or authorized side effect.

Before execution, construct `CurrentExpectation::freeze(&prepared, next_generation, &independent_policy, Profile::Fixture)`. The prepared run supplies its private full WorkKey, and the controller independently supplies current GE EligibilityPolicy: expected binding, producer/analyzer versions, coverage, contract digest, action and principal sets. Never construct expectations by copying a returned report. Production profile and deserialization reject. Controller policy is counted before cloning, capped at 256 KiB with bounded scope/principal collections.

Register and execute using the existing history APIs. Append and publish maintain their existing CAS semantics. Consumption requires both the current stored WorkKey and current generation to match the pre-frozen expectation; merely looking up the same task or candidate is insufficient. New registration clears the pointer, failed current attempts cannot fall back to old success, and late old completions remain historical only.

`freeze_git` and `register_git` accept an already verified `GitPreparedRun` and preserve its private full key, including GG candidate membership/configuration digest. They do not accept raw envelopes. The history retains the original domain output, not a persisted `GitEvidenceBundle`; retain that separate bundle when external Git artifact transport is needed. Actual candidate preparation still runs through GG before the bridge. Local fixture assessment is not production queue authentication.

On each consume, SpecGuard verifies immutable domain/engine bytes, asks `ConsumptionClock` for current time, validates the exact current baseline if bound, calls its approval port freshly, and invokes real GE `evaluate_eligibility` against actual contract/facts/report bytes and the independent policy. `SystemConsumptionClock` reads the host clock; custom clocks and authority ports are controller-owned trust inputs, not authenticated by this library. Clock failure or pre-epoch time fails closed.

A baseline-bound expectation requires full current baseline and `BaselineCheck` approval authority; a previously cached `ValidatedBaseline` is deliberately not accepted. Baseline repository, qualified scope and digest must match exactly. Baseline inputs are capped at 1 MiB and 512 graph rows before authentication clones. Changed state, expired/revoked approval and unavailable authority reject consumption. Unbound evidence cannot silently acquire a supplied baseline.

An absent envelope TTL does not suppress any check. Approval records require a valid interval; absence of that information is unsupported, not indefinite authorization. Even a controller's very long validity interval does not skip current revocation or input checks. Nothing caches an authority response. Partial/error/cancelled/BLOCK evidence cannot be repaired by approval. The returned `FixtureConsumption` exposes the GE assessment and original technical decision; it never rewrites archived reports or claims a production producer identity.

Tests in `tests/evidence_invalidation.rs` cover candidate/base/group/source/policy/profile/baseline/scope/limit and repo/task/worktree drift; independently changed analyzer/version/coverage/contract expectations; fresh producer/baseline authority queries and expiry/revocation/unavailability; clock errors; two targets, late completion and failed-current isolation. `tests/queue_binding.rs` exercises real SHA-1/SHA-256 clean Git preparation and changed member ordering despite identical envelope binding. `tests/consumption_budget.rs` measures rejection of a 17 MiB action before an owning clone. Existing concurrency tests remain unchanged. Task 3.7 awaits independent review.
