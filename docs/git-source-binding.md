# Local exact Git source binding

`integration::git_binding` adds a separate `specguard.git-source/v1alpha1` SDK profile. Existing advisory producer/CLI semantics remain intact. The dependency is the reviewed GitGuard `Repository` and `read_commit_files` implementation (c33b28a plus52f07b0 bounded runner), without privileged-execution features. No Git safety runner is copied into SpecGuard. Current package rust-version is1.90; actual1.90 lib and Git-path tests pass. This dependency supports the reviewed Unix environment, not a newly qualified Windows/WASM target.

`GitSourcePolicy::freeze(source_policy, required, protected_mapping)` freezes and hashes the exact source policy, requirement set and structural mapping plus profile version. The GitGuard CandidateSnapshot must carry that policy digest and exactly matching qualified requirement IDs. Candidate/base/member OIDs and declared clean state are validated by GG, with bounded context limits before validation. Candidate source reads come from GG's fsck-checked private object database, not the checkout or branch HEAD. Only regular UTF8-path files are supported; symlinks/gitlinks, unsafe/unsupported paths and resource limits fail closed. Files are materialized in a private temporary directory solely to reuse established discovery/freeze/parser behavior. No source scripts, hooks, filters, checkout or source instructions execute.

`GitPreparedRun::prepare(&repository, &candidate, &policy, Attempt)` captures exact committed bytes and returns a consuming prepared run. `binding()` exposes the complete SG RunBinding **before execution**. A controller must pin this binding with its own protected candidate/policy context; deriving expectations from a returned envelope would defeat the check. `work_key()` also includes the full GG candidate binding digest in the profile identity, covering members, paths, group and policy beyond the SG binding fields. The independently scoped SpecGuard snapshot digest is retained; it is not replaced with GG's digest. A separate full-file digest records actual modes, OIDs and contents.

Standard prepare analyzes immutable committed content even if the working tree is dirty or at an older HEAD. This is explicit local advisory evidence: CandidateSnapshot.clean remains false. `prepare_clean` additionally requires the GG-observed candidate tree to match actual worktree and index at preparation. GG verification re-observes that clean field and rejects stale clean claims. Neither mode authenticates queue membership, controller/provider identity, approval or merge eligibility. A synthetic candidate created by real GG merge preview is supported without pretending it is the branch HEAD. The current GG candidate profile rejects baseline references; this wrapper therefore cannot assert an approved specification baseline.

`execute` uses the existing bounded native structural producer/cooperative runtime. `GitEvidenceBundle::verify/load` requires the caller's independently pinned candidate, policy and prepared binding; unknown fields/version and oversized JSON are rejected. It checks all wrapper identities, runs actual GE/domain verification, rebuilds SG source from the actual immutable candidate tree and compares the prepared source binding/file digest. For completed runs it reruns actual analysis and compares raw contract/facts/report/domain bytes, so a self-consistent but fabricated graph cannot pass by merely updating artifact digests. Error/cancelled bundles remain null-decision evidence, not successful content checks. Current references retain local advisory semantics; no signed authority is created.

Limits include64KiB candidate context,64 members/requirements,1024 allowed-path prefixes, SG16MiB aggregate source/policy admission and wrapper wire size, plus GG reader/runner and existing native parser limits. These intentionally conservative limits are not an OS-wide allocation or deadline guarantee. Optional dirty/clean checks and source-policy changes remain visible in candidate/profile identity. No CLI flag or hosted provider was added.

Tests in tests/queue_binding.rs use actual temporary repositories, both SHA1/SHA256, actual GG synthetic commits, dirty old HEAD, later working-file mutation, policy/base/group changes, committed symlink rejection and a rehashed fabricated domain that passes generic recomputation but fails this committed-source verifier. Existing source/parser/trace/CLI/history tests remain in the full suite.
