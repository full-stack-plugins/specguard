# Source and parser admission profile

The read-only Unix source profile uses descriptor no-follow reads and detects inode, size, timestamp and byte drift. It does not promise an OS-atomic multi-file snapshot. Absolute paths, parent traversal, source symlinks and non-regular files reject. Relative source paths are limited to 4096 bytes before filesystem traversal. Root namespace/authority strings are limited to 256 bytes and format strings to 128 bytes, preventing metadata amplification across discovered files.

Policy limits may narrow, but cannot expand, these ceilings: 1000 roots/files, 1MiB per file, 10,000 lines per source, depth 64 and 30,000ms per cooperative phase. Defaults remain 1000 files, 1MiB, 10,000 lines, depth 16 and 5000ms. Discovery and freeze additionally limit total admitted source bytes to 16MiB. Metadata uses the existing 16MiB counting-writer admission. These are deliberate compatibility restrictions on formerly unbounded policy settings and aggregate captures; callers must handle diagnostics and incomplete coverage.

Discovery also admits retained diagnostic/entry metadata and pending traversal paths against one monotone 16MiB budget shared by all roots. Borrowed field lengths are charged before cloning or formatting paths, with a sixfold JSON escaping allowance and collection/row overhead. Visited work is counted globally (at most `2 * max_files + 1`), including failed and overlapping files; it no longer resets per root. Exhaustion stops traversal with a reserved static Limit diagnostic declaring the remaining scope unknown. Returning an inventory with this diagnostic is incomplete, never an empty successful coverage result. This intentionally makes large overlapping-root configurations more restrictive.

Every public parser call now applies the existing producer construction preflight before cloning metadata or constructing nodes. It permits at most 4096 aggregate source lines and a conservative 16MiB estimated construction cost, including repeated source-path/namespace references and a byte multiplier. Oversized input yields an explicit `<snapshot>` Limit with no nodes and no copied untrusted binding. This estimate is not an allocator quota. Native Markdown retains its event count ceiling (`max_lines * 32`), actual AST nesting checks and per-event time checks; explicit parsing also checks time per line. The grammar, native identity registry and trace adapters remain intact.

Discovery uses a shared elapsed-time check while traversing. Freeze checks time before Git verification, before each capture/revalidation, and around aggregate digest work. Legacy Git object verification now delegates to GitGuard's reviewed repository/runner, which validates copied object storage, bounds output/storage and supervises each fixed Git subprocess with a timeout of at most 5000ms. It accepts only exact commit OIDs and matching object formats. Source object symlinks/alternates and other storage outside that supported profile now fail closed. No source-provided command is executed, and temporary copied Git storage is separate from the source repository. Exact candidate-tree binding remains the separate `GitPreparedRun` API; legacy freezing remains advisory with respect to dirty bytes.

Time limits for Rust filesystem/serialization/parser work are cooperative checkpoints, not forced OS deadlines: a currently running syscall, serializer step or Markdown parser step may complete before the next check. Git subprocess deadlines apply per invocation; freeze rejects at the next overall checkpoint if its phase budget expired. No global RSS ceiling or hard real-time guarantee is claimed.

`tests/security_limits.rs` exercises inert injection text, byte/file/depth/time gaps, frozen tamper, direct parser amplification, path length, policy ceilings, aggregate bytes, zero freeze time, a real 1ms Git rejection and symlinked Git object storage. Existing source/native/trace suites retain absolute/parent/symlink/FIFO, SHA-1/SHA-256, nested AST and candidate binding regressions. The external `specguard-security-limits-report.md` records exact dependency pins, RED/GREEN logs and measurements. Task 4.2 stays unchecked until independent review.
