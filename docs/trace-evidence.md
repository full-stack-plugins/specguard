# Declared requirement / source / execution trace

Trace is a read-only consumer of native OpenSpec or Spec Kit requirements and TestGuard signed execution evidence. It does not infer Java/Rust semantic correctness from a path or marker. It never grants approval. Formal change: GuardEngine `execution-trace-evidence`.

```json
{
  "schema_version": "specguard.trace/v1",
  "source": "openspec",
  "execution_plan_digest": "sha256:<canonical frozen TestGuard plan digest>",
  "mappings": [{
    "artifact": "openspec/specs/auth/spec.md",
    "requirement_id": "Login",
    "code": [{"path": "src/auth.rs", "marker": "pub fn login"}],
    "tests": ["auth::tests::login"]
  }]
}
```

`source` is `openspec` or `speckit`, selected explicitly. Each defined native requirement must appear exactly once by artifact + native ID. Removed requirements are excluded. Code paths are project relative normal paths; traversal, links/reparse points, external files and missing markers fail. Markers are literal declarations, not parsed symbols or semantic claims. Empty test obligations fail. Mapping budgets: 8192 mappings, 128 code references per mapping, 1024 reads total, 1MiB per file and 16MiB total. Shared source snapshot budgets also apply. JSON is bounded to 4MiB. Inputs are never fetched remotely.

```text
specguard trace check --project ABS --manifest ABS
specguard trace check --project ABS --manifest ABS --evidence ABS --public-key ABS
specguard trace verify --project ABS --manifest ABS --evidence ABS --public-key ABS --report ABS
```

Check without evidence returns `INDETERMINATE` (exit 3) when declarations are structurally valid. Failed mappings or rejected evidence return `FAIL` (2). Arguments / unreadable inputs return 4. `PASS` (0) requires shared `guard_evidence::verify_execution`: pinned external public key, valid Ed25519 signature, TestGuard successful process, explicit plan digest, current complete project snapshot, current executable/artifact bytes, nonempty required/observed tests and age ≤86400 seconds. Every mapped test ID must be in both required and observed sets. No key is auto-generated by the consumer.

Keep receipt/report/log outputs outside the project so writing a report does not itself change the candidate snapshot. Freeze manifest before running tests if it is inside the project. `trace verify` fully recomputes the report and compares every field with the supplied old report. It does not trust an old PASS. Any source, manifest, receipt or artifact change requires a new execution/check; do not rewrite reports to erase failures.

MCP `specguard_check_trace` takes `project`, `manifest`, optional paired `evidence` / `public_key`; `specguard_verify_trace` adds required `report`. Both share the CLI and reject mutation arguments. Reports use `specguard.trace-report/v1`; `semantic_validation` and `approval_status` always remain `NOT_EVALUATED`.

Validation: `cargo test --offline` includes isolated consumer signature fixtures, missing/invalid mappings, repair/recheck, stale source, changed artifact, missing executed test, signature tampering and full report recomputation. Isolated signed fixtures test the consumer contract; they are not claimed as real Maven/Cargo executions. The unified integration suite must exercise the real producer.
