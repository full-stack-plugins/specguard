# Local protected-policy CI exercise

Run `cargo run --locked --example ci_protected_policy` on Linux with `/usr/bin/git` available. No arguments, network, installer, hosted CI API or external repository are accepted. The example constructs private temporary Git repositories, emits three JSON summaries, and removes its temporary files. It is an assertion-based reproducible exercise, not a service or an untrusted-command runner.

The protected controller in `mod.rs` pins SpecGuard 0.1.0 / `specguard.structural` analyzer version 1, four enforced relation rules, the `demo:R1` obligation, and the exact `specs/a.md` source profile. These constants belong to the example binary; `.guard-policy.json` committed by the candidate is never loaded as policy. `GitSourcePolicy` also binds that configuration into GitGuard's advisory candidate snapshot. The current exact candidate and base are actual Git objects. The SG source-scoped binding is frozen from `GitPreparedRun::binding()` **before execution**, together with independently fixed producer, contract digest, required coverage and principal/action policy.

The owned SG producer runs against committed Git bytes. `GitEvidenceBundle::verify` reopens the candidate and compares actual domain/engine artifacts against the protected source profile. Only that owned execution issues a private identity record. There is no public arbitrary-digest registration: a digest is a lookup key, not a signature. Current GuardEngine `evaluate_eligibility` consumes the original engine artifact bytes and independently frozen expectations, with the explicit identity adapter `specguard.example.local-ci/v1`. The fixture timestamp and principal are controller constants, not host identity or trusted time discovery. Producer revocation and provider unavailability are queried on every consumption; no eligibility cache exists. No approval grant or domain write capability exists.

Expected cases: valid source yields technical ALLOW / eligible; missing acceptance plus candidate-authored empty rules yields technical BLOCK / technical_block; unsupported source remains partial and cannot qualify. Tests additionally reject an unissued rehashed run, analyzer drift, candidate/base/source/contract drift, missing or weakened coverage, revoked authority and provider failure. Technical decisions are preserved. A matching public hash never restores authority.

The example hashes refs, HEAD, raw index, both tracked files and porcelain status immediately before and after the producer/verification job; JSON includes both hashes. Git fixture setup creates commits, but the measured analysis job does not mutate the source repository. The Linux GitGuard reader still creates its bounded private object store. This is not a sandbox guarantee for arbitrary candidate programs; candidate programs are never executed. The temporary repository is discarded after the exercise, so the returned summary is not a reusable production authorization.

This fulfills a local CI integration exercise only. No hosted required check has been deployed, no production issuer is selected, no repository-origin identity is authenticated, and SARIF is neither generated nor used as authority. Local-process controller trust is explicit. Reviewed source pins and executed validation are recorded in the implementation ledger; changing the binary/policy requires a new reviewed pin.
