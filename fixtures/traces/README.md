# Explicit trace source / artifact fixture

These are actual `markdown-explicit/v1` requirement, `markdown-adr/v1` ADR and `markdown-task/v1` task files frozen from a real temporary Git repository. `trace.json` was generated by `cargo run --locked --example generate_trace_fixture -- fixtures/traces`; snapshot.json/provenance.json retain the binding and source bytes. The commit is a local fixture commit with dirty source bytes separately digested, not authenticated queue evidence.

Target files require YAML frontmatter with exact `format` and `namespace`, then H2 `ADR: ID` or `Task: ID` headings. IDs are explicit ASCII alphanumeric/period/underscore/hyphen names, scoped by namespace. Other heading levels and unknown formats fail closed. Fenced code and blockquotes do not declare targets. This is a narrow native file adapter owned by SpecGuard, not blanket compatibility with every ADR/task convention.

Requirement Markdown list directives `traces_to_adr: namespace:ID` and `traces_to_task: namespace:ID` attach to the preceding parsed requirement in that file. Unknown reserved `traces_to_` relations are incomplete. Fenced/quoted examples are data. Existing native requirement parsing remains the separate established adapter; these fixtures exercise the explicit-ID requirement profile.

Read-only commands:

```
specguard trace-check ROOT POLICY.json BINDING.json REQUIRED.json
specguard trace-export ROOT POLICY.json BINDING.json REQUIRED.json
```

Both emit the separate strict `specguard.trace/v1alpha1` artifact on stdout. Exit 0 means complete and no structural findings; 2 means findings or incomplete scope; 4 means invocation/capture/export failure. They never write sources, publish reports, authenticate approvals or operate Git refs. Policy/binding/required JSON are explicit inputs, not inferred from candidate contents. The command validates real Git objects; it does not claim a clean candidate or policy authority.

The shared producer borrowed-size/parser admission checks run before snapshot copies or parser allocation; per-source byte/line limits also apply. Unsupported/malformed target files preserve coverage gaps and cannot become definite missing targets. Consumers should validate the schema and required external scope, and retain source/candidate binding when using the artifact.
